# MSA-4-PaymentService

Проектная работа спринта 4: архитектура Saga-оркестрации обработки платежа для компании OrchestrPay.

## Структура репозитория

| Директория | Содержимое |
|---|---|
| [Task1](Task1) | Реестр транзакций Saga: состав шагов, их типы (компенсируемая / необратимая / повторяемая) и компенсации |
| [Task2](Task2) | Таблица переходов состояний платежа, включая ветки антифрод-проверки и cut-off (опциональное задание, выполнено) |
| [Task3](Task3) | ADR: размещение функции оркестрации — отдельный сервис vs встраивание в доменный сервис |
| [Task4](Task4) | BPMN-диаграмма процесса (PNG + исходный `.bpmn`, Camunda Modeler) |
| [Task5](Task5) | Таблица интеграционных и end-to-end тест-кейсов |

## Связность артефактов

Артефакты не независимы, а описывают одну и ту же архитектуру на разных уровнях детализации:

- Имена шагов из реестра **Task1** — это имена задач на BPMN-диаграмме **Task4**.
- Состояния и переходы **Task2** реализованы развилками и событиями BPMN-модели **Task4**, покрываются тест-кейсами **Task5**.
- Направление ADR в **Task3** (отдельный сервис-оркестратор на BPM-движке) — прямое следствие того, что **Task4** уже проектирует процесс как BPMN-диаграмму, а не встроенную в доменный сервис логику.

Проектная работа охватывает архитектуру и тест-план; реализация оркестрации в коде в её состав не входит.
