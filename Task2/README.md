# Task 2. Таблица переходов состояний платежа

State machine, управляющая экземпляром Payment Saga. Состояние персистится оркестратором, что позволяет восстановить процесс после перезапуска и обеспечивает удержание транзакции на время ручной проверки.

## Состояния

| Состояние | Описание | Терминальное |
|---|---|---|
| `PAYMENT_CREATED` | Платёж зарегистрирован, сага инициализирована, финансовых эффектов нет | нет |
| `FUNDS_DEBITED` | Средства списаны со счёта клиента и зарезервированы на техническом счёте платформы | нет |
| `ANTIFRAUD_PENDING` | Выполняются автоматические проверки: внутренние правила FraudCheck, а также AML и GeoRisk параллельно | нет |
| `MANUAL_REVIEW_PENDING` | Ожидание решения оператора антифрода. Активен cut-off-таймер на 20 минут | нет |
| `ANTIFRAUD_APPROVED` | Получено разрешение на проведение транзакции | нет |
| `ANTIFRAUD_REJECTED` | Получен запрет на проведение транзакции | нет |
| `TRANSFER_IN_PROGRESS` | Выполняется перевод средств контрагенту. Pivot-точка ещё не пройдена | нет |
| `COMPENSATING` | Выполняется автоматическая компенсация: возврат средств клиенту и отмена платежа | нет |
| `COMPLETED` | Платёж успешно проведён, средства у контрагента, клиент уведомлён | **да** |
| `REFUNDED` | Платёж не проведён, средства возвращены клиенту в полном объёме, клиент уведомлён | **да** |
| `REJECTED` | Платёж отклонён до списания средств, финансовых эффектов не было | **да** |

## Таблица переходов

| Исходное состояние | Переходное состояние | Событие |
|---|---|---|
| — | `PAYMENT_CREATED` | `PaymentInitiated` — клиент оформил заказ и инициировал платёж |
| `PAYMENT_CREATED` | `FUNDS_DEBITED` | `AccountDebited` — средства успешно списаны со счёта клиента |
| `PAYMENT_CREATED` | `REJECTED` | `DebitFailed` — списание невозможно: недостаточно средств, счёт заблокирован или превышен лимит |
| `FUNDS_DEBITED` | `ANTIFRAUD_PENDING` | `AntifraudCheckStarted` — запущены проверки FraudCheck, AML и GeoRisk |
| `ANTIFRAUD_PENDING` | `ANTIFRAUD_APPROVED` | `AntifraudAllowed` — все проверки вернули разрешение |
| `ANTIFRAUD_PENDING` | `ANTIFRAUD_REJECTED` | `AntifraudDenied` — хотя бы одна проверка вернула запрет |
| `ANTIFRAUD_PENDING` | `MANUAL_REVIEW_PENDING` | `ManualReviewRequired` — проверка вернула решение «ручная проверка» |
| `ANTIFRAUD_PENDING` | `MANUAL_REVIEW_PENDING` | `AntifraudUnavailable` — внешние провайдеры недоступны после исчерпания retry, решение эскалируется оператору |
| `MANUAL_REVIEW_PENDING` | `ANTIFRAUD_APPROVED` | `OperatorApproved` — оператор разрешил транзакцию в пределах 20 минут |
| `MANUAL_REVIEW_PENDING` | `ANTIFRAUD_REJECTED` | `OperatorDenied` — оператор запретил транзакцию в пределах 20 минут |
| `MANUAL_REVIEW_PENDING` | `ANTIFRAUD_APPROVED` | `CutOffTimerExpired` — истёк cut-off-time, применяется разрешение по умолчанию |
| `ANTIFRAUD_APPROVED` | `TRANSFER_IN_PROGRESS` | `TransferStarted` — начат перевод средств контрагенту |
| `TRANSFER_IN_PROGRESS` | `COMPLETED` | `TransferSucceeded` — перевод подтверждён контрагентом, pivot-точка пройдена |
| `TRANSFER_IN_PROGRESS` | `COMPENSATING` | `TransferFailed` — перевод не выполнен после исчерпания retry, средства остались на техническом счёте |
| `ANTIFRAUD_REJECTED` | `COMPENSATING` | `CompensationTriggered` — запущен автоматический откат саги |
| `COMPENSATING` | `COMPENSATING` | `RefundFailed` — возврат не прошёл, назначен повтор с экспоненциальной задержкой |
| `COMPENSATING` | `REFUNDED` | `FundsRefunded` — средства возвращены клиенту, платёж отменён |

## Побочные действия при входе в состояния

Уведомления не образуют отдельных состояний саги: это повторяемые шаги, выполняемые при входе в состояние.

| Состояние | Выполняемые шаги |
|---|---|
| `ANTIFRAUD_REJECTED` | `NOTIFY_SECURITY` — уведомление службы безопасности с деталями решения |
| `COMPLETED` | `SEND_NOTIFICATION_CLIENT` — уведомление об успешном платеже |
| `REFUNDED` | `SEND_NOTIFICATION_CLIENT` — уведомление о возврате средств |
| `REJECTED` | `SEND_NOTIFICATION_CLIENT` — уведомление об отклонении платежа |

## Ключевые сценарии

**Антифрод вернул отказ.** `FUNDS_DEBITED` → `ANTIFRAUD_PENDING` → `ANTIFRAUD_REJECTED` (событие `AntifraudDenied`, срабатывает `NOTIFY_SECURITY`) → `COMPENSATING` → `REFUNDED`. Средства возвращаются клиенту автоматически, Customer Support не привлекается.

**Сработал cut-off.** `MANUAL_REVIEW_PENDING` → `ANTIFRAUD_APPROVED` по событию `CutOffTimerExpired`. Транзакция проводится, как если бы оператор её разрешил. Факт применения решения по умолчанию фиксируется в истории саги отдельным признаком, чтобы такие транзакции можно было отобрать для пост-фактум-анализа службой безопасности.

**Подтверждение операции.** `ANTIFRAUD_APPROVED` → `TRANSFER_IN_PROGRESS` → `COMPLETED`. Единственный путь в `COMPLETED` проходит через успешный перевод.

**Ручная проверка.** `ANTIFRAUD_PENDING` → `MANUAL_REVIEW_PENDING` и далее одна из трёх развилок: `OperatorApproved`, `OperatorDenied` или `CutOffTimerExpired`. Всё время ожидания транзакция удерживается в персистентном состоянии, средства уже списаны и лежат на техническом счёте платформы.

## Примечания

**Из `TRANSFER_IN_PROGRESS` есть выход в компенсацию.** Это не противоречит статусу `TRANSFER_TO_MERCHANT` как необратимого шага: pivot-точка считается пройденной только при подтверждённом успехе перевода. Пока перевод не подтверждён, деньги находятся на техническом счёте платформы, и откат возможен.

**`COMPENSATING` имеет переход сам в себя.** Компенсация не имеет права завершиться неуспехом: при ошибке возврата сага остаётся в `COMPENSATING` и повторяет попытку. Отсутствие выхода из этого состояния в разумный срок — признак зависшей саги, который должен отлавливаться отдельным автоматическим контролем (сканирование `payments` на записи в `COMPENSATING` дольше ожидаемого времени).

**Из `COMPLETED` нет обратных переходов.** Возврат по факту мошенничества, обнаруженного после завершения транзакции, — это отдельный бизнес-процесс со своей сагой, а не переход в рамках этой state machine.

**Правило cut-off противоречит критичному требованию и это осознанный компромисс.** Требование «стоимость ошибки при проведении транзакции значительно выше, чем потенциальная потеря от её отклонения» предписывает при неопределённости отклонять, а cut-off предписывает разрешать. Бизнес выбрал доступность: заблокированный на 20 минут платёж — гарантированная потеря конверсии и обращение в Customer Support, тогда как доля мошеннических транзакций среди попавших на ручную проверку и не разобранных вовремя мала. Компенсирующая мера — обязательная фиксация признака «решение принято по cut-off» и пост-фактум-разбор таких транзакций службой безопасности.
